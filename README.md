# Portfolio

**ภาษา:** [ไทย](#ภาษาไทย) · [English](#english)

เว็บพอร์ตโฟลิโอของ นายเจิน ชง กวา (zhen chong) โรงเรียนเลยพิทยาคม — รวมผลงานการแข่งขัน โครงงาน และการอบรม

## ภาษาไทย

### เริ่มใช้งาน

ดับเบิลคลิก `index.html` เปิดในเบราว์เซอร์ได้เลย ไม่ต้องติดตั้งอะไรทั้งสิ้น

> **ทำไมถึงเปิดจากไฟล์ตรงๆ ได้**
> เพราะสคริปต์ทุกตัวเป็น `<script>` ธรรมดา ไม่ใช่ `type="module"`
> ES module ถูกกฎ CORS ของเบราว์เซอร์บล็อกเมื่อ origin เป็น `null` (ซึ่งคือกรณี `file://`)
> ทุกไฟล์จึงห่อตัวเองด้วย IIFE แล้วฝากของที่ต้องใช้ร่วมกันไว้ที่ `window.PF`
> ข้อแลกเปลี่ยนคือ **ลำดับของ `<script>` ในหน้า HTML สำคัญ** — `icons.js` กับ
> `data/projects.js` ต้องมาก่อน และ `main.js` ต้องอยู่ท้ายสุดเสมอ

### สามอย่างที่ต้องแก้ก่อนเผยแพร่

**1. ชื่อ อีเมล และโซเชียล** → `assets/js/data/projects.js` ตรงตัวแปร `SITE`

```js
const SITE = {
  name:   "zhenchong",          // ← เปลี่ยนเป็นชื่อจริงที่อยากให้แสดง
  email:  "lpk37943@loeipit.ac.th",
  origin: "https://lpk37943-cyber.github.io/portfolio",
  socials: [ /* ใส่ลิงก์จริง ตัวที่เป็น "#" จะถูกซ่อนอัตโนมัติ */ ],
};
```

อีเมลจะเปลี่ยนตามทุกหน้าเอง เพราะ HTML ใช้ `data-site-email` เป็นที่วาง
ส่วนชื่อ "zhen chong" ใน nav กับ footer เขียนไว้ใน HTML ตรงๆ ถ้าจะเปลี่ยนต้องค้นแทนทุกหน้า

**2. ที่อยู่เว็บ** → ค้นหา `lpk37943-cyber.github.io/portfolio` ในไฟล์ `.html` ทุกไฟล์
แล้วแทนด้วยโดเมนจริง จำเป็นเพราะ `og:image` **ต้องเป็น URL เต็มเสมอ** —
ตัวขูดข้อมูลของ LINE/Facebook ไม่ได้เปิดหน้าเว็บ มันแค่ดึง HTML มาอ่าน `<head>`
จึงอ่าน path แบบสัมพัทธ์ไม่ออก อย่าลืมแก้ `sitemap.xml` กับ `robots.txt` ด้วย

**3. รูปตัวเอง** → อ่าน [`assets/img/README.md`](assets/img/README.md)
ภาพผลงานย้ายเข้ามาครบแล้วจาก `D:\ผลงาน\` เหลือ **3 ไฟล์** ที่ยังเป็นภาพแทนที่ —
วางไฟล์จริงทับตามชื่อได้เลยโดยไม่ต้องแก้โค้ด

| ไฟล์ | ใช้ที่ไหน |
|---|---|
| `assets/img/hero-bg.jpg` | ฉากหลังเม็ดจุดของหน้าจอแรก |
| `assets/img/portrait-card.jpg` | รูปในบัตรห้อยสายคล้อง (3:4) |
| `assets/img/portrait.jpg` | รูปวงกลมในหน้า about (1:1) |

### เพิ่มผลงานใหม่

1. เพิ่มอ็อบเจกต์ใน `PROJECTS` ที่ `assets/js/data/projects.js`
2. ก๊อป `work/ai-inventor.html` เป็น `work/<slug>.html` แล้วแก้สามที่:

4. เพิ่มบรรทัดใน `sitemap.xml`

### โมดูล JavaScript (17 ตัว)

ทุกตัวห่อด้วย IIFE แล้วฝากของไว้ที่ `window.PF` — ลำดับ `<script>` จึงสำคัญ

| โมดูล | ทำอะไร |
|---|---|
| `media` | ภาพ/วิดีโอที่ไฟล์ยังไม่มี → สร้าง SVG แทนอัตโนมัติ |
| `halftone` | รูปถ่ายขึ้นเป็นเม็ดจุดคอมิกก่อน แล้วคลี่เป็นรูปจริง (ตัวเอฟเฟกต์เป็น CSS) |
| `reel` | **หน้าแรกเท่านั้น** — ฟิล์มสตริปผลงานตรึงจอแล้วไถลข้างตาม scroll |
| `spine` | เส้นลายวงจร PCB ที่ขอบซ้าย บอกว่าอ่านมาถึงไหน จุดบัดกรีติดไฟตามหัวข้อ |
| `render` | สร้าง HTML จาก `data/projects.js` — การ์ด · ดัชนีผลงาน · เกียรติบัตร · หน้า case study |
| `nav` | แถบบนติดกระจกตอนเลื่อน · เมนูมือถือ · scrollspy |
| `tabs` | แท็บ ผลงาน/เกียรติบัตร/ทักษะ · ตัวกรองหมวด |
| `ui` | toast · สลับธีม · คัดลอกอีเมล · lightbox · ฟอร์มติดต่อ |
| `palette` | command palette (⌘K) · คีย์ลัด |
| `reveal` | เนื้อหาโผล่ตอนเลื่อนมาถึง · ตัวเลขนับขึ้น |
| `type` | ข้อความเผยทีละบรรทัด + สลับตัวอักษรมั่วก่อนลงตัว (ใช้ `Intl.Segmenter` ตัดคำไทย) |
| `fx` | เคอร์เซอร์กำหนดเอง · แสงตามเมาส์ · ฉากเปิดใยแมงมุมที่ฉีกออก |
| `lanyard` | บัตรห้อยสายคล้อง ฟิสิกส์ Verlet ลากได้ |
| `formes` | รูปทรงวิศวกรรมลอย ลากได้ โผล่เฉพาะหน้าจอแรก |
| `scenes` | section ถอยห่างตอนเลื่อนพ้น + parallax |
| `smooth` | scroll มีแรงเฉื่อย (ขยับตำแหน่งจริง ไม่ใช่ transform ทั้งหน้า) |
| `comic-fx` | **หน้าแรกเท่านั้น** — canvas อนุภาคตามเมาส์ · การ์ดเอียง · glitch · แผงพรีวิว |

> ⚠️ `comic-fx` กับ `reel` มีอยู่หน้าเดียว `main.js` จึงต้องเรียกด้วย `PF.initComicFx?.()` และ `PF.initReel?.()`
> ถ้าเรียกตรงๆ อีก 9 หน้าจะโยน TypeError กลางคัน `boot()` แล้วทุกอย่างใต้บรรทัดนั้น
> จะไม่ทำงานเลย — ปุ่มธีม · lightbox · ฟอร์ม · palette ตายหมดโดยที่หน้ายังดูปกติ
> (เคยพังมาแล้วจริงทั้ง 9 หน้า)

### โมชั่นกราฟิก

เว็บนี้เคยมีฉากสามมิติเป็นพื้นหลังทั้งเว็บ เขียน WebGL ดิบเองหกไฟล์ 88 KB
มีแขนกล **Dobot Magician** ลากหมุนได้ที่หน้า `work/dobot.html`

**ถอดออกทั้งหมดแล้ว** เหตุผลคือเว็บนี้ใช้ยื่นเข้ามหาวิทยาลัย กรรมการเปิดดูบน
เครื่องอะไรก็ไม่รู้ การแบกริบท WebGL ไว้ทุกหน้าแลกกับความเสี่ยงว่าจะพัง ช้า
หรือกินแบต ไม่คุ้มกับสิ่งที่ได้กลับมา — ของที่มาแทนเบากว่ามาก ไม่มีทางพัง
และปิดตัวเองอัตโนมัติเมื่อผู้ใช้ตั้งค่าลดการเคลื่อนไหว

| ที่ไหน | เป็นอะไร | อยู่ไฟล์ไหน |
|---|---|---|
| ฉากหลังทุกหน้า | กริดแบน + วงแสงสามวงเคลื่อนช้ามาก | `.ambient` ใน `motion.css` |
| หน้าแรก ครึ่งขวา | รูปเม็ดจุดเป็นฉากหลัง (ซ่อนบนมือถือ) | `.hero-shot` ใน `pages.css` |
| หน้าแรก ใต้คอลัมน์ | ลูกโป่งคำพูด ยุบตอนชี้ เด้งตอนกด | `.comic-bubble` ใน `pages.css` |
| หน้าแรก ชื่อ | ขอบสีเหลื่อม · แตกร่างสามสี · วงหมึก · ขยับตามเมาส์ | ฮุก `data-*` บน `<h1>` → `components.css` |
| หน้าแรก ขวามือ | บัตรห้อยสายคล้อง ลากเล่นได้ ฟิสิกส์ Verlet จริง (ซ่อนบนมือถือ) | `modules/lanyard.js` |
| `work/dobot.html` | แขนกล SVG เล่นท่าหยิบ-วางเอง | `.armviz` ใน `pages.css` |
| รูปถ่ายทุกใบ | เป็นภาพพิมพ์เม็ดจุดถาวร สีกลับมาตอนชี้เมาส์ | `[data-halftone]` ใน `components.css` |
| ฉากโหลด | ตัวนับ 000→100 + ชื่อประกอบตัวจากเม็ดจุด | `initIntro` ใน `modules/fx.js` |
| หน้าแรก ใต้แถบเครื่องมือ | ฟิล์มสตริปผลงานตรึงจอแล้วไถลข้าง | `modules/reel.js` + `.reel` ใน `pages.css` |
| ขอบซ้ายทุกหน้า | เส้นลายวงจร PCB บอกความคืบหน้าการอ่าน | `modules/spine.js` + `.spine` ใน `components.css` |
| ปุ่มทุกปุ่ม | เอียงเข้าหาเมาส์ก่อนเมาส์ไปถึง | `initMagnet` ใน `modules/fx.js` |

#### หน้าจอแรก

คอลัมน์เดียวเรียงลงมาในกล่องเดียวกับทุก section — ป้ายสถานะ → ชื่อ → บทบาท →
คำแนะนำตัว → ชิปทักษะ → ลิงก์ลงไปดูผลงาน → บรรทัดรางวัล
บัตรห้อยสายคล้องอยู่ขวามือ ถ่วงน้ำหนักกับคอลัมน์ข้อความ

| | ค่า | ทำไม |
|---|---|---|
| ขนาดชื่อ | `--t-name` = `min(6.6vw, 13vh)` | ~107px บนจอ 1620px ใหญ่กว่า `--t-h1` ชัดเจนแต่ยังอยู่ในคอลัมน์ได้ |
| ตัวพิมพ์ | **เล็ก** ไม่ใช่ใหญ่ | ชื่อคนไม่ใช่หัวข้อ ตัวพิมพ์ใหญ่อ่านเป็น "ป้ายประกาศ" ตัวพิมพ์เล็กอ่านเป็น "การแนะนำตัว" |
| `line-height` | 1.02 | ตัวพิมพ์เล็กมีหางบนหางล่าง ถ้าบีบเท่าตัวพิมพ์ใหญ่ หาง g จะชนหัว d บรรทัดถัดไป |
| `margin-left` | `-.047em` | ชดเชยช่องไฟข้างของ z ตัวเล็ก วัดด้วย `measureText` (กฎข้อ 11) |

> **เคยลองแบบโปสเตอร์เต็มจอมาแล้ว แล้วถอยกลับ — บันทึกไว้กันทำซ้ำ**
>
> ตอนนั้นชื่อกินเต็มความกว้างจอที่ 192px ตัวพิมพ์ใหญ่
> ปัญหาไม่ได้อยู่ที่ตัวมันเอง แต่อยู่ที่มัน **บังคับให้ทุกอย่างรอบตัวต้องหลบ**:
> รูปต้องย่อ · บัตรห้อยต้องย้ายจุดยึด · ลูกโป่งต้องหาที่ใหม่ · และพื้นรอง
> `--hero-scrim` ต้องกลับทิศทุกครั้ง เพราะปลายชื่อทับรูปเสมอ (วัดได้ 304px ที่จอ 1280)
> ทุกครั้งที่ขยับอย่างหนึ่ง อีกสามอย่างพังตาม — แก้อยู่สามรอบกว่าจะครบ
>
> พอชื่อกลับมาอยู่ในคอลัมน์ ปัญหาทั้งชุดหายไป: ตัวหนังสือกับรูปแยกกันคนละครึ่งจอ
> อยู่แล้วโดยโครงสร้าง ไม่ต้องคำนวณคอนทราสต์รายชิ้นตามตำแหน่งอีก
> (วัดจริง: ข้อความยาวสุดจบที่ 806px ส่วนรูปเริ่มทึบที่ 1121px บนจอ 1620px)

#### รูปเม็ดจุดหลังชื่อ กับลูกโป่งคำพูด

| ของ | อยู่ตรงไหน | หมายเหตุ |
|---|---|---|
| `.hero-shot` | ชิดขวา เต็มความสูง กว้าง `min(52vw, 880px)` | mask จางซ้าย (เว้นที่ตัวหนังสือ) + จางบน (เว้นที่ nav) |

| `IDEAS IN MOTION` | ช่องว่างซ้ายเหนือชื่อ | ลูกของ `.hero-poster` เฉพาะจอ ≥ 94rem |

> ⚠ **ลูกโป่งต้องเกาะ element จริง ห้ามเกาะขอบจอ**
> เคยให้ทั้งสองใบลอยเกาะ `bottom` ของ `.hero` แล้วมันไปทับบรรทัดรางวัล
>
> ต้นเหตุคือความสูงของคอลัมน์ไม่คงที่ — เปลี่ยนตามความสูงจอ (ชื่อใช้
> `min(6.6vw, 13vh)`) และตามจำนวนบรรทัดที่ย่อหน้าไทยตัดคำได้ในแต่ละความกว้าง
> สองตัวแปรนี้ขยับคนละทิศ จึงไม่มีค่า `bottom` ไหนปลอดภัยทุกจอ
> วัดจริงที่ 1620×900 เหลือช่องว่างแค่ **11px** จอเตี้ยกว่านั้นนิดเดียวก็ชน
>
> ตอนนี้ผูกกับของที่ขยับไปพร้อมกับมัน: `CLICK ME!` เป็นสมาชิกของแถวชิป
> ส่วน `IDEAS` เป็นลูกของ `.hero-poster` ทั้งคู่จึงเลื่อนตามคอลัมน์เสมอ
>
> ทั้งคู่มี `static` เป็นค่าตั้งต้น จอที่ที่ว่างไม่พอจะไหลต่อท้ายเนื้อหาเอง
> เกณฑ์ **94rem** ของ `IDEAS` คำนวณมา ไม่ได้กะ: ที่ 1504px กล่อง poster เริ่มที่
> 112px ลูกโป่งกว้าง 130px จึงเหลือระยะจากขอบจอ 22px — แคบกว่านี้จะถูก
> `overflow: hidden` ของ `.hero` ตัดหายครึ่งใบ

#### ฉากโหลด — ตัวนับที่บอกความจริง

ฉากใยแมงมุมที่ฉีกออกยังอยู่เหมือนเดิม แต่เพิ่มตัวนับ `000→100` กับชื่อที่ประกอบตัว
ขึ้นจากเม็ดจุดหยาบ 16px ไปละเอียด 3px (mask ตารางจุด ขนาดผูกกับ `--intro-p`)

ตัวนับ**ไม่ได้นับตามเวลาเฉยๆ** แต่ผูกกับงานที่รออยู่จริงสองอย่าง — `document.fonts.ready`
กับ `window load` เหตุผลที่ต้องรอฟอนต์: ชื่อบนหน้าจอแรกสูงเกือบ 200px และตั้ง
`text-wrap: nowrap` ถ้าฉากฉีกก่อนฟอนต์มา คนดูจะเห็นชื่อด้วยฟอนต์สำรองหนึ่งจังหวะ
แล้วมันกระตุกเปลี่ยนความกว้างทั้งบรรทัด — เห็นชัดมากที่ขนาดนี้

ตัวเลขที่โชว์คือค่าที่ "ช้ากว่า" ระหว่างความคืบหน้าจริงกับเวลาขั้นต่ำ 1100ms
ถ้าโชว์ความคืบหน้าล้วน มันจะกระโดด 0→100 ในเฟรมเดียวตอนโหลดจากแคช
ถ้าโชว์เวลาล้วน มันก็โกหกว่าโหลดเสร็จทั้งที่ยังไม่เสร็จ · เพดาน 2600ms กันติดค้าง

ชื่อในฉากเปิดจบที่ **ภาพพิมพ์ ไม่ใช่ตัวอักษรทึบ** โดยตั้งใจ — เพราะสิ่งที่รออยู่หลัง
ฉากฉีกคือรูปเม็ดจุดเต็มจอ ถ้าจบที่ตัวทึบ ตาจะอ่านเป็นของคนละชุด

#### เม็ดจุดบนรูปถ่าย

ซ้อน "จานสกรีน" (`radial-gradient` ปูซ้ำ) ทับรูป ผสมด้วย
`background-blend-mode: overlay` แล้วดันด้วย `filter: contrast(22)` ให้เหลือขาว-ดำล้วน
วงขาวกว้างกลายเป็นจุดใหญ่ วงแคบกลายเป็นจุดเล็ก = halftone จริงที่โตตามความสว่าง

**สองโหมด — "เอกสาร" กับ "รูปถ่าย"** (`data-ht-mode`)

| โหมด | ใช้กับ | พฤติกรรม |
|---|---|---|
| ค่าตั้งต้น (ไม่ระบุ) | เกียรติบัตร | คลี่ทันทีที่เลื่อนมาถึง |
| `hold` | รูปถ่ายทุกใบ | ค้างเป็นภาพพิมพ์ สีกลับมาตอนชี้เมาส์ |

ตอนแรกทำเป็นคลี่เหมือนกันหมด ผลคือเอฟเฟกต์นี้เห็นได้แค่ 800ms ต่อรูปหนึ่งใบ
แล้วหายถาวร — 95% ของเวลาที่คนดูอยู่บนหน้า เว็บก็หน้าตาเหมือนพอร์ตทั่วไปทุกประการ
พอให้มันค้าง มันเลิกเป็น "ทรานซิชัน" แล้วกลายเป็น "หน้าตาของเว็บ"

เกียรติบัตรไม่ค้างเพราะมันคือ **หลักฐานที่กรรมการต้องอ่านตัวหนังสือบนใบจริง**
ถ้าปล่อยให้เม็ดจุดค้าง = ซ่อนหลักฐาน · บนจอสัมผัสที่ไม่มี hover รูปถ่ายก็กลับไป
ใช้กฎเดียวกับเอกสาร เพราะรูปผลงานคือเนื้อหา ส่วนเม็ดจุดคือการนำเสนอ

> **ทำไมไม่ใช้ canvas ซึ่งแม่นกว่า** — วิธีมาตรฐานคืออ่านความสว่างรายพิกเซลด้วย
> `getImageData()` ซึ่งใช้กับเว็บนี้ไม่ได้เลย เพราะเปิดจาก `file://` แล้วเบราว์เซอร์
> ถือว่าไฟล์แต่ละไฟล์คนละ origin พอ `drawImage` รูปในเครื่อง canvas จะถูก
> "ย้อมสี" (tainted) แล้ว `getImageData` โยน `SecurityError` ทิ้ง
> เอฟเฟกต์จะพัง **เฉพาะตอนดับเบิลคลิกไฟล์** ซึ่งเป็นวิธีเปิดหลักของเว็บนี้พอดี
> และจะดูปกติดีตอนทดสอบผ่านเซิร์ฟเวอร์ — บั๊กแบบที่หายากที่สุด

ชั้นเม็ดจุดต้อง **ทึบ** ห้ามใส่ `mix-blend-mode` — เคยลอง `screen` แล้วรูปสีเดิม
ทะลุขึ้นมาเต็มความเข้ม เม็ดจุดกลายเป็น "มุ้งลวดสีขาวทับรูป" ไม่ใช่ภาพพิมพ์
ภาพพิมพ์จริงคือหมึกสีเดียวบนกระดาษ ไม่มีต้นฉบับอยู่ข้างหลังให้เห็น

จานสกรีนกลับขั้วตามธีม (`--ht-screen` ใน `tokens.css`) — พื้นมืดใช้หมึกขาวบนพื้นดำ
โหมดกระดาษใช้หมึกดำบนพื้นขาว ถ้าไม่กลับ โหมดสว่างจะเป็นแผ่นดำทึบทั้งใบ

#### ฟิล์มสตริปตรึงจอ

ค่าตั้งต้นคือแถบเลื่อนแนวนอนที่ปัดเองได้ ใช้ `scroll-snap`
ของเบราว์เซอร์ ซึ่งทำงานแม้ JS ตายสนิท แล้ว `reel.js` ค่อย **อัปเกรด** เป็นโหมดตรึง
เมื่อเช็คแล้วว่าเครื่องไหว (เมาส์จริง · ไม่ปิดแอนิเมชัน · จอกว้าง ≥ 62rem · สูง ≥ 520px)

กลับด้านความเสี่ยงแบบนี้เพราะถ้าคำนวณพลาดบนเครื่องกรรมการ สิ่งที่เขาจะเห็นคือ
**ช่องว่างเปล่าสูงหลายจอที่เลื่อนผ่านไม่ได้** ซึ่งแย่กว่าไม่มีเอฟเฟกต์มาก

ส่วนนี้ติด `data-sticky` เพื่อบอก `scenes.js` ว่าห้ามใส่ `scale` ให้ —
`scale` ทำให้มันกลายเป็น containing block แล้ว `position: sticky` ข้างในเลิกตรึงทันที

ขนาดแผงคำนวณจาก **ความสูงจอ** (`58svh × 4/3`) ไม่ใช่ความกว้าง เพราะตอนตรึง
เรากำลังยัดหัวข้อ + แผง + รางลงในหนึ่งจอพอดี ความสูงจึงเป็นข้อจำกัดจริง

**ฟิล์มสตริปไม่ได้มาแทนดัชนีบรรทัด** — ทั้งคู่อยู่ในหน้าแรกด้วยกันเพราะทำคนละหน้าที่:
ฟิล์มสตริปทำให้ "รู้สึก" (ภาพใหญ่ทีละชิ้น) ดัชนีทำให้ "รู้" (หกบรรทัด กวาดตารวดเดียวเห็นครบ)
กรรมการต้องได้ทั้งสองอย่าง ถ้ามีแค่ฟิล์มสตริปจะต้องเลื่อนหกรอบเพื่อตอบว่า
"เด็กคนนี้ได้รางวัลอะไรบ้าง" ทั้งคู่อ่านจาก `PROJECTS` ชุดเดียวกัน จึงไม่ผิดกฎข้อ 5

#### เส้นลายวงจร PCB

ตำแหน่งจุดบัดกรีคำนวณจากตำแหน่งจริงของ section ในเอกสาร
หารด้วยความยาวหน้า เส้นนี้จึงเป็น **แผนที่ย่อของหน้า** ไม่ใช่ของตกแต่ง
หน้าไหนไม่มี `section[id]` (หน้า case study ทั้งหก) จะถอยไปใช้หัวข้อ `h2`
ในเนื้อหาแทน ซึ่งก็คือโครงเรื่องของหน้านั้นอยู่แล้ว

เส้นหักมุม 45° ไม่ใช่ 90° เพราะลายวงจรจริงทำแบบนั้น (มุมแหลมทำให้น้ำยากัดกรด
ค้างแล้วเซาะเส้นขาด) ตำแหน่งถูกวางให้อยู่ในช่องว่างขอบซ้ายพอดี วัดแล้วเหลือ
ระยะห่างจากตัวหนังสือ 34px ที่จอ 1200px

#### ปุ่มแม่เหล็ก + เคอร์เซอร์ป้าย VIEW

ปุ่มเอียงเข้าหาเมาส์ และเคอร์เซอร์
กลายเป็นวงกลมมีคำว่า VIEW / ZOOM / OPEN เมื่อลอยเหนือของที่เปิดดูได้

> ⚠️ แม่เหล็กเขียนลง `transform` **ห้ามเขียนลง `translate`**
> ปุ่มคอมิกใช้ `translate` ไปแล้วสำหรับเอฟเฟกต์ "กดจมลงไปหาเงา"
> (`.btn--primary:hover { translate: 2px 2px }`) ถ้าเขียนทับ เอฟเฟกต์นั้นหายทั้งเว็บ
> CSS แยก `transform` กับ `translate` เป็นคนละคุณสมบัติที่ประกอบกันเองตามลำดับ
> `translate → rotate → scale → transform` จึงอยู่ด้วยกันได้โดยไม่ต้องแก้กฎปุ่มเดิม

เคอร์เซอร์ป้ายใช้ `mix-blend-mode: difference` กลับสีทุกอย่างที่อยู่ข้างใต้
ป้ายจึงอ่านออกทั้งบนพื้นมืด พื้นสว่าง และบนรูปถ่าย โดยไม่ต้องรู้ล่วงหน้าว่าข้างใต้สีอะไร

#### แขนกล SVG ยังตรงกับเครื่องจริงทุกตัวเลข

ตอนถอด WebGL ออก สเปกทั้งหมดถูกคัดมาไว้เป็นคอมเมนต์หัวบล็อกใน `pages.css`
ตัวเลขจึงยังสาวกลับได้ว่ามาจากไหน ไม่ได้กะเอาใหม่

- ขีดจำกัดมุม **J1 ±90° · J2 0–85° · J3 −10–95°** เป็นค่าของ Dobot Magician จริง
- หัวจับตั้งฉากกับพื้นเสมอ เพราะจำลองกลไกสี่เหลี่ยมด้านขนานด้วยการหมุนกลับ `−(J2+J3)`
  ที่กลุ่ม `.armviz-wrist` — วัดแล้วได้ 0.00° ทุกคีย์เฟรม
- ทุกท่าในลำดับหยิบ-วางคำนวณย้อนกลับด้วยกฎโคไซน์ ไม่ได้กะมุมเอา
  ตรวจจาก DOM แล้วได้ระยะเอื้อม 2.208 กับความสูง 0.345 หน่วยตอนแตะชิ้นงาน
  ตรงกับที่คำนวณไว้ในโค้ดเดิมทุกตำแหน่ง

**ทำไมต้องมีสองภาพ** — J1 หมุนในระนาบแนวนอน ภาพด้านข้างแบนๆ จึงแสดงไม่ได้
ถ้าทำมุมมองเดียวจะโกหกผู้ชมทันที แต่ตัวเลขของโจทย์จริงแก้ให้เอง:
แท่นหยิบกับแท่นวางอยู่ที่รัศมี **2.205 หน่วยเท่ากันทั้งคู่** และมุมฐานคือ
`atan(1.358 / 1.737) = 38°` ซึ่งตรงกับ `j1 = ±38` ในลำดับท่าเป๊ะ
แขนจึงหมุนฐานอย่างเดียว ไม่ยืดไม่หด แยกเป็นสองภาพได้โดยไม่มีอะไรถูกบิด

- **ภาพด้านข้าง** J2/J3 เป็นการหมุนจริงในระนาบ แท่นวางปรากฏเป็นจุดเดียว
- **หน้าปัดด้านบน** J1 กวาดจากแท่นซ้ายไปขวา — ที่ที่การย้ายชิ้นงานเกิดขึ้นจริง

#### รายละเอียดที่ทำให้มันไม่ใช่แค่ภาพขยับ

- **easing อยู่ในทุกคีย์เฟรม ไม่ใช่ที่ตัว element** — CSS ให้แต่ละคีย์เฟรมกำหนด
  easing ของช่วงที่เริ่มจากตัวเองได้ ซึ่งจำลอง `smoothstep()` รายช่วงของโค้ดเดิม
  ได้พอดี มอเตอร์จึงออกตัวและเบรกทุกท่า ถ้าตั้งครั้งเดียวที่ element
  จะกลายเป็นแขนไหลเรื่อยๆ ไม่มีจุดหยุด
- **รอบละ 10 วินาที ไม่ใช่ 9** — ตารางท่าเดิมจบที่ท่าพักแล้ววนกลับไปเริ่มที่ท่าอื่น
  ไหล่จึงกระตุก 7° ทุกครั้งที่ครบรอบ (ของเดิมมีปัญหานี้เหมือนกันแต่ถูกกลบด้วย
  การหน่วงใน `rig.js`) แก้โดยให้ 0% กับ 100% เป็นท่าพักทั้งคู่ แล้วเลื่อนทั้งตาราง
  ไปอยู่ช่วง 10–100% ด้วยสูตร `เปอร์เซ็นต์ = 10 + t × 90` — ช่วงทำงานยังยาว
  9 วินาทีเท่าเดิม ส่วนวินาทีที่เพิ่มมาคือการออกจากและกลับสู่ท่าพัก
- **ชิ้นงานใช้กล่องสองใบสลับกัน** เพราะ CSS ย้ายพ่อแม่ของ element ไม่ได้
  ใบหนึ่งอยู่ในกลุ่มข้อมือ อีกใบวางนิ่งบนแท่น สลับตรงจังหวะที่ค่า grip เดิม
  ข้ามครึ่งพอดี ซึ่งเป็นตอนที่หัวดูดแตะผิวกล่องอยู่แล้ว สองใบจึงทับกันสนิท
- **ทุกอย่างเป็น `rotate` · `scale` · `opacity` ล้วน** อยู่บน compositor
  ไม่แตะ layout ไม่ repaint

#### ฉากหลัง

วงแสงสามวงเป็น `radial-gradient` ที่ฟุ้งอยู่แล้วในตัว ขยับด้วย `translate` อย่างเดียว
คาบไม่หารกันลงตัว (43 · 61 · 79 วินาที) จึงไม่มีจังหวะไหนที่ทั้งสามวงกลับมาเรียง
เหมือนเดิม ตาจับรูปแบบซ้ำไม่ได้

ที่ไม่ใช้ `background-position` หรือ `filter: blur()` แบบเคลื่อนไหว เพราะตัวแรก
บังคับ repaint เต็มจอทุกเฟรม ตัวหลังบังคับ GPU ให้เบลอใหม่ทุกเฟรม แพงกว่าฉาก 3D
ที่เพิ่งถอดออกไปเสียอีก

#### เมื่อผู้ใช้ปิดแอนิเมชัน

บล็อก `prefers-reduced-motion` ท้าย `motion.css` จับด้วย `*` จึงปิดทั้งหมดให้เอง
ไม่ต้องเขียนเงื่อนไขเพิ่มที่ไหนอีก — ต่างจากฉาก 3D เดิมที่ต้องเช็ค `matchMedia`
เองใน JavaScript

ท่าตั้งต้นของแขนถูกตั้งไว้ที่ตัว element เป็น **ท่าพัก** (J2 30° · J3 76°)
พอแอนิเมชันถูกปิด ค่าจะกลับมาที่นี่ ผู้ใช้จึงยังเห็นแขนในท่าที่ถูกต้อง
ไม่ใช่ท่าประหลาดหรือบล็อกที่หายไปทั้งก้อน

#### คลาส `.plate` ถูกลบไปแล้ว

เคยมีแผ่นทึบชื่อ `.plate` ห่อเนื้อหาไว้ เป็นมรดกจากยุคที่ยังมีฉาก 3D —
แขนกลสีขาว (`#d9dbe3`) luminance 0.72 ทำให้ตัวหนังสือที่นั่งบนพื้นหลังตรงๆ
เหลือ contrast **1.19:1** ต้องมีพื้นทึบอย่างน้อย 98.6% ถึงจะแก้ได้

พอฉาก 3D ถูกถอด แผ่นนี้ก็ไม่เหลือหน้าที่ แต่ยังค้างอยู่จนกลายเป็นปัญหาเสียเอง:
ทุกก้อนเนื้อหามีกรอบของตัวเอง หน้าจึงเป็นกำแพงการ์ดซ้อนกัน — **ลบทิ้งแล้ว**
ตอนนี้เนื้อหานั่งบนผืนผ้าใบตรงๆ ใช้ที่ว่างกับขนาดตัวอักษรแบ่งกลุ่มแทนเส้นขอบ

`--card-face` · `--pill-face` ใน `tokens.css` ยังอยู่ ใช้กับการ์ดผลงานและชิป

วัดจริงล่าสุด (ทุกคู่ผ่าน WCAG):

| | โหมดมืด | โหมดกระดาษ |
|---|---|---|
| `--ink` | 16.8:1 | 18.9:1 |
| `--ink-soft` | 5.9:1 | 7.0:1 |
| `--ink-faint` | 4.9:1 | 5.6:1 |
| `--ink-dim` (ตัวใหญ่) | 3.5:1 | 3.4:1 |
| `--accent-ink` | 6.3:1 | 6.7:1 |

### กฎที่ห้ามแหก

1. **ห้าม hardcode สีหรือขนาด** ในไฟล์ CSS อื่น — ต้องอ้าง `var()` จาก `tokens.css`
   ถ้ามีสามหน้าที่เขียนสีเทาคนละเฉดกันเพราะกะเอาเอง จะไม่มีใครรู้ตัวจนกว่าจะเห็นพร้อมกัน
2. **ตัวหนังสือขนาดปกติห้ามจางกว่า `--ink-faint`** (4.6:1 ผ่าน WCAG AA)
   `--ink-ghost` (1.4:1) ใช้ได้เฉพาะของตกแต่งที่ลบทิ้งแล้วไม่มีใครเสียข้อมูล
3. **แอนิเมชันทุกตัวต้องอยู่ใน `motion.css`** ไม่งั้นมันจะหลุดจากบล็อก
   `prefers-reduced-motion` ท้ายไฟล์ที่ปิดทุกอย่างพร้อมกัน
4. **ห้ามใช้ `type="module"`** ด้วยเหตุผลเรื่อง `file://` ข้างบน
5. **เนื้อหาเดียวกันห้ามเขียนสองที่** — ถ้ามันโผล่มากกว่าหนึ่งหน้า มันควรอยู่ใน `projects.js`
6. **ชั้นฉากหลังห้ามกินคลิก** — `pointer-events: none` เสมอที่ `.ambient`
   ถ้าลืม ลิงก์และปุ่มทั้งหน้าจะกดไม่ได้ เพราะมันคลุมเต็มจอ
7. **ภาพเคลื่อนไหวต้องยังอ่านรู้เรื่องตอนหยุดนิ่ง** — สิ่งที่ขยับต้องตั้งค่าตั้งต้น
   ไว้ที่ตัว element ด้วย ไม่ใช่พึ่ง `@keyframes` อย่างเดียว เพราะเมื่อผู้ใช้ตั้ง
   `prefers-reduced-motion` แอนิเมชันจะจบทันทีแล้วค่ากลับไปที่ค่าตั้งต้น
   ถ้าค่าตั้งต้นไม่ได้ตั้งไว้ จะเห็นเป็นท่าประหลาดหรือของหายไปทั้งก้อน
8. **ของที่แบกตัวหนังสือบนพื้นลายต้องมีพื้นทึบ** — ห้ามใช้ `rgba(255,255,255,.0X)`
   เปล่าๆ เป็นพื้นหลัง ให้ใช้ `var(--card-face)` หรือ `var(--pill-face)`
   (คลาส `.plate` ที่กฎข้อนี้เคยอ้างถึงถูกลบไปแล้ว — ดูหัวข้อข้างบน)
9. **โมดูลที่ไม่ได้มีครบทุกหน้าต้องเรียกด้วย `?.`** — เช่น `PF.initComicFx?.()`
   ถ้าเรียกตรงๆ หน้าที่ไม่มีไฟล์นั้นจะโยน TypeError กลางคัน `boot()` แล้วทุกอย่าง
   ใต้บรรทัดนั้นตายหมดโดยที่หน้ายังดูปกติ — หาสาเหตุยากมาก
10. **ลูปแอนิเมชันต้องหยุดเองเมื่อไม่มีอะไรเปลี่ยน** — `fx` (เคอร์เซอร์) ·
   `lanyard` (บัตรห้อย) · `comic-fx` ทุกตัวหยุดเมื่อนิ่ง แล้วปลุกเมื่อมีเหตุ
   ถ้าปล่อยให้วนตลอดจะกินเฟรมทิ้งโดยไม่เปลี่ยนภาพอะไรเลย
11. **ทั้งเว็บมีขอบซ้ายเส้นเดียว** — nav · ชื่อบนหน้าจอแรก · แถบเครื่องมือ ·
   ฟิล์มสตริป · เนื้อหาทุก section ต้องเริ่มที่ x เดียวกันทุกความกว้างจอ
   ห้ามตั้ง `max-width` หรือขอบของตัวเองให้ชิ้นไหนเป็นการเฉพาะ

   กฎนี้เกิดจากของจริงที่พังมาแล้ว: ครั้งหนึ่งหน้าเดียวกันมีขอบซ้ายสี่ตำแหน่ง
   (22px ชื่อ · 64px แถบเครื่องมือ · 100px แบรนด์ใน nav · 144px เนื้อหา)
   แต่ละชิ้นดูดีเมื่อดูแยกกัน พอมาอยู่ด้วยกันหน้าเว็บอ่านออกมาว่า "แปลก"
   โดยที่บอกไม่ถูกว่าเห็นอะไร — ตาคนจับเส้นตั้งที่ไม่ตรงกันได้เก่งมาก

   ⚠ สองกับดักที่เจอตอนแก้:
   - `.nav` เอา padding ไว้นอกกล่อง ส่วน `.container` เอาไว้ในกล่อง
     ถ้าให้ `max-width` เท่ากันดิบๆ ขอบจะห่างกันเท่า `--pad-x` บนจอกว้าง
     (ดู `calc(var(--w-content) - var(--pad-x) * 2)` ใน `components.css`)
   - ตัวอักษรมี "ช่องไฟข้าง" ติดมาเสมอ ชื่อตัวใหญ่ต้องดึงกลับด้วย
     `margin-left` ติดลบ **ที่วัดมาจริง** ไม่ใช่กะเอา — ใช้
     `canvas.measureText().actualBoundingBoxLeft` ที่ฟอนต์และน้ำหนักจริง

## English

A portfolio site for competitions, projects and training programmes.
Written in plain HTML/CSS/JavaScript — **no framework, no build step, no dependencies**.

**Getting started:** double-click `index.html`. That's the whole setup.

Scripts are classic `<script>` tags rather than ES modules, because module scripts are
blocked by CORS under the `file://` protocol (origin `null`). Every file wraps itself in
an IIFE and shares through a single `window.PF` namespace, so script order in the HTML
matters — `icons.js` and `data/projects.js` first, `main.js` last.

**Before publishing, change three things:**

1. Name, email and social links — `assets/js/data/projects.js`, the `SITE` object
2. Site origin — search every `.html` for `lpk37943-cyber.github.io/portfolio`
   (`og:image` must be an absolute URL; social scrapers don't run JS or resolve
   relative paths), plus `sitemap.xml` and `robots.txt`
3. Images — see [`assets/img/README.md`](assets/img/README.md). Every slot currently
   renders a generated SVG placeholder; drop real files in with the documented
   filenames and they take over with no code change.

**Adding a project:** append to `PROJECTS` in `data/projects.js`, copy any
`work/<slug>.html` and change its `<title>`, meta tags and `<body data-case="">`.
Case study content is generated from the data at runtime.

**Motion graphics:** the site used to run a hand-written WebGL scene (six files, 88 KB)
with a draggable Dobot Magician arm. That was removed — this portfolio is submitted to
universities and gets opened on unknown machines, so carrying a WebGL context on every
page was not worth the risk of it breaking, stalling or draining the battery.

What replaced it is mostly CSS and SVG: a halftone-dot and grid backdrop with three very
slow drifting light blobs (`base.css`, `.ambient` in `motion.css`), the draggable
Verlet-physics lanyard card in the hero (`modules/lanyard.js`), draggable floating
engineering shapes that fade out past the first screen (`modules/formes.js`), and an SVG
arm on `work/dobot.html` that plays the pick-and-place cycle by itself (`.armviz` in
`pages.css`).

There is exactly one 2D canvas, on the landing page only (`modules/comic-fx.js`): pointer
particles, card tilt and a preview panel. It is 2D context — not WebGL — it never runs on
touch devices or under `prefers-reduced-motion`, and its loop idles at zero cost when
nothing is moving. The same idle rule applies to the cursor and lanyard loops.

**The first screen is a single column.** Status pill, name, role, introduction, skill chips,
a link down to the work, and the award line — stacked in the same box every other section
uses, with the draggable lanyard card hanging on the right to balance it. The name is set
lowercase at `min(6.6vw, 13vh)`: a name is not a headline, and uppercase reads as signage
rather than an introduction.

The halftone photograph occupies the right half that the column does not use, and the speech
bubbles float in the bottom-left corner — both sit outside `.hero-poster` so neither can
push the column's order around. Because text and image now own separate halves by
construction, contrast stops being a per-element calculation: the longest line ends at 806px
while the photo only becomes opaque at 1121px on a 1620px screen.

A full-bleed poster version was built and then rolled back, which is worth recording so it
is not attempted again. At 192px edge to edge it looked striking, but it forced everything
around it out of the way — the photo had to shrink, the lanyard needed a new anchor, the
bubbles needed somewhere else to live, and `--hero-scrim` had to be re-aimed every time
because the name always crossed the photo (304px of overlap at 1280). Each adjustment broke
the other three.

That scrim's direction is tied to where the text lives: vertical while the name sat at the
bottom, flipped when it moved to the top, and horizontal now that text is left and image is
right. Moving the photo above or below the text again means rotating it again.

On phones the photo is hidden rather than dimmed. The column spans the full width there, so
text always crosses the image, and the maximum opacity that still clears contrast is set by
`--ink-dim` at **0.005** — invisible anyway. Dimming cannot solve it; only removal can.

**Rules the code holds itself to:** no hardcoded colours or sizes outside `tokens.css`;
body text never lighter than `--ink-faint` (4.6:1, WCAG AA); every animation lives in
`motion.css` so one `prefers-reduced-motion` block disables all of them; nothing is
written in two places.
